# Cutroom

A small, local video review studio. Play edits, leave comments on a moment or range, mark what to keep or change, and carry feedback into the next cut.

## Open the studio

On this Mac, double-click **Start Studio.command**. It starts the studio and opens **http://127.0.0.1:4317**. Opening it again reuses the running studio.

On a fresh machine, install **Node.js 22.13 or later** and **FFmpeg** (including ffprobe), then:

```sh
npm ci
npm run build
npm start
```

For development, `npm run dev` serves the API and Vite together on port 4317. Rebuild after changing source code before reopening the production launcher.

## Review a cut

- Choose a video in **All cuts**. Press **Space** to play/pause, arrows to move 5 seconds, and Shift + arrows to move a frame.
- Press **C** or **Add comment** to pause and pin a note to the playhead.
- Choose **Note**, **Keep this**, or **Change**. Enable **Time range** to mark an entire section.
- Click a note’s timestamp or timeline marker to jump back. Reply, edit, resolve/reopen, or delete notes.
- Use **Review status** to mark a cut approved or request changes.
- **Export feedback** downloads Markdown with cut names, original video paths, timecodes, replies, and resolution states.
- The profile control changes the name on future comments. Cmd/Ctrl + Enter posts a comment. Unposted drafts survive switching cuts in this browser.

## Add another project or edit

Use **New project** and **Add video**. Choose a file to copy it into the studio, or use **Link local file** to reference an existing file without duplication. Adding a cut leaves all older cuts and comments intact. An H.264 MP4 is the safest browser preview; this app does not transcode or destructively edit camera originals.

Agents can add revisions directly:

```sh
npm run import -- --project "Walk & talk" --file "/absolute/path/new-cut.mp4" --title "07 — Revised opening" --description "Shorter hook, softer lighting"
npm run feedback
```

Importing the same file path through the CLI is idempotent. Give each new render a new filename so older notes continue to refer to the exact reviewed version. Linked files must remain at their original paths. Uploaded files are managed under `data/media/`.

## Where feedback lives

Everything persistent is in `data/`, excluded from Git:

- `studio.sqlite`: authoritative project, cut and comment database (WAL mode).
- `feedback.json`: atomically updated, readable feedback snapshot after every change. Codex can read this file directly when you ask for a new edit. Snapshot timecodes refer to the rendered video, not raw camera timecodes.
- `feedback.md`: generated by `npm run feedback`.
- `media/`: uploaded video copies; `thumbnails/`: generated previews.
- `studio.log`: launcher logs.

The source repo deliberately contains no videos, comments, local paths or credentials. Back up the entire `data/` folder while the app is stopped, plus any externally linked videos. The private repository backs up code, not review data.

## Scope and privacy

This is a single-user studio bound to `127.0.0.1`. It persists across browser restarts, has local timecoded links, and rejects cross-origin mutations. It does not expose a public review link, synchronize between computers, or provide cloud accounts. The running app is independent from the private GitHub repository. Do not expose this server through a public tunnel without adding authentication and a storage/deployment plan.

To stop it, find the process with `lsof -iTCP:4317 -sTCP:LISTEN`, then terminate that Node process; opening the launcher starts it again. `PORT` and `STUDIO_DATA_DIR` can override the defaults. No background login item is installed.

## Checks

```sh
npm test         # persistence, validation, replies, exports, local-origin and range serving
npm run build    # TypeScript and production bundle
npm run test:e2e # isolated browser workflow; creates its own test database and small video
```

Browser tests use the locally installed Google Chrome channel; change the Playwright configuration if needed. The project uses React/Vite, Express, and Node’s built-in SQLite module. API reference: [Node SQLite](https://nodejs.org/api/sqlite.html), [Express](https://expressjs.com/en/5x/api/).
